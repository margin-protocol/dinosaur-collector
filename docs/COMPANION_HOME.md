# 日常首頁、獨立培育與入住安排

## 這一版能操作的內容

首頁改為共同生活空間，保留小恐龍引導、今日願望與研究者手記。孵化前顯示等待相遇的狀態；已收集的小湘可安排最多三位同時展示。這是手機場景的展示上限，沒有降低圖鑑或收藏數量上限。

新增獨立 `#incubate` 培育頁。蛋、培養架、生命訊號、餵能量與破殼全部集中在這裡，首頁入口只顯示孵化百分比或可破殼提示。完成願望後能直接去培育，破殼揭曉後可一起回首頁。首頁不再包含蛋的圖層。

入住安排只列已收集的角色，可取消／加入，允許全部休息，選擇刷新後保留。滿三位時要先讓一位休息；新角色在有空位時自動加入，滿員則保留原成員，收藏仍增加；重複孵化沿用原本化石獎勵。

點角色可打招呼。原味小湘使用原有待機、走路、坐姿動畫；活動區域依住戶數分配，角色離頁、開啟對話框或頁面背景化時停止，返回恢復。替換住戶時清理動畫計時器與 resize 監聽。尊重 reduced-motion。

## 素材與概念稿的差距

**只有 No.001 原味小湘具備正式立繪與三組動畫。No.002–004 的立繪與動畫尚未提供**，角色素材 fallback 改用有長髮、衣服、手腳與靴子輪廓的 Q 版人形剪影（`_placeholder.png`），實際多人截圖仍是剪影預覽。沒有把原味換色假裝成完成的其他角色，也沒有把概念圖當成遊戲背景。

核准概念稿中的草莓／睡衣造型、喝飲料動作、家具與特殊互動仍是美術示意，這一版不宣稱已完成。後續交付對應 `assets/characters/<image>.webp`／`.png` 後，既有 fallback 會優先顯示正式立繪；其他角色動畫需再依美術規格接入。首頁繼續使用原有房間與小恐龍素材。

## 資料相容

原遊戲存檔 `siang-collector:v1` 的結構與規則不變。入住偏好另存 `siang-collector:residents:v1`（角色編號陣列）。舊存檔沒有偏好時選擇前三位已收集角色；空陣列表示使用者明確安排全部休息；損壞資料回到預設，未知、未收集與重複編號會被過濾。跨分頁監聽兩個 key。

沒有更改 HSV 色彩判斷、每日三願望、每項 +35、蛋的能量門檻、抽卡權重與重複化石數值。首蛋孵化、揭曉、收藏寫入仍先完成存檔，再演出。首頁角色安排不增減資源或解鎖角色。

## 驗證與截圖

Chromium 觸控模式：360／390／430 × 844，另測 612 高度。以指定寬度直接比對 innerWidth 與 scrollWidth，不依賴自動放大的 viewport。頁尾不蓋住操作，主內容正常捲動。

- 原有照片辨色、三次成功共 +105、刷新保留完成、培育扣 10、首蛋揭曉、新角色回首頁、跨日、失敗照片不發獎。
- 入住三位上限、只選已收集、取消全部後刷新保留、替換後刷新保留、偏好損壞、無效／重複編號過濾。
- 切換住戶前後原遊戲 JSON 相同，跨分頁同步入住安排。
- 預設滿員且尚未存偏好時，新角色也不擠掉舊成員；重複孵化只給原有化石，不新增住戶。
- 正常模式逐格動畫、鍵盤打招呼、入住對話框暫停／恢復、離頁暫停、瀏覽器返回、Escape 關閉。
- 抽屜標題、功能名稱與小字一併統一字體，包含原字體修正 PR 的變更。

`docs/review/`：

- `chromium-home-*`：未孵化首頁。
- `companion-single-*`：一位正式角色的首頁。
- `companion-three-*`：三位住戶的佈局測試，另兩位使用佔位素材。
- `companion-residents-*`：入住安排。
- `chromium-incubate-*`：獨立培育頁。
- `chromium-live-actor-390`：正常動畫模式。

多人及入住截圖的已收集資料由隔離的測試 fixture 建立，沒有解鎖玩家存檔。iOS Safari／Android Chrome 真機相機仍待驗收；此環境 WebKit 缺少系統函式庫，不能宣稱 Safari 核心或真機已通過。

## 重跑

啟動 `python3 -m http.server 8000`，安裝 Playwright 後執行：

```sh
node tests/mobile.cjs
node tests/room.cjs
node tests/interaction.cjs
```

可設 `CHROMIUM_ONLY=1` 跳過 WebKit，`CHROMIUM_PATH=/usr/bin/chromium` 使用現有 Chromium；預先安裝 Playwright 的環境可設定 `NODE_PATH`。
